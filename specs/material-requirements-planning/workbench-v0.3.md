## 如何使用

1. 双击项目 material-planning 目录中的“启动工作台.cmd”，浏览器会打开 http://127.0.0.1:8765 。启动窗口需要保持运行；如果服务已经运行，直接打开网址，不必重复启动。
2. 先试算默认的“多任务争用库存”。左侧四个页签可编辑、增加、删除物料、BOM、库存和任务；删除物料不会自动删除引用，计算时会明确提示不一致。
3. 在右侧设置基准日并勾选任务，点击“生成计划”。编号引用应对应，库存快照日期须与基准日一致。优先级1最高，优先于交期分配库存。
4. 在下方查看生产量、采购量、采购余量和日期。展开明细可查看库存分配与BOM路径。输入错误显示中文提示，行字段错误提供“定位”按钮；交期风险保留原日期。

当前工作区不保存数据，刷新或关闭页面会丢失编辑内容。修改任意数据/选中任务会清除旧结果；异步计算期间输入变化时，返回结果不再展示。载入示例覆盖编辑前会询问，离开有编辑的页面时浏览器会提示。

输入框数量暂限JavaScript安全整数范围；更大的输入会阻断而非静默取整。Python计算产生的更大整数，通过本地接口以文本形式准确展示。数量仍采用之前的整数规则。

## 视觉与实现

采用克制的工具界面风格：白色 #FFFFFF、背景 #FAFBFC、边框 #E8EBEF、正文 #252A31、主要操作 #2867A5。微软雅黑为主，左侧宽表格与右侧窄计算栏形成明确主次，窄屏改成纵向布局，宽表格可横向滚动。去掉大标语、编号装饰和重复说明，数值列采用等宽数字。

保持现有HTML/CSS/JavaScript结构，未为样式更换技术栈或引入构建依赖。界面事件及业务协调均为函数，没有新增自定义类。后端使用Python标准库WSGI适配现有planner.py，只监听127.0.0.1；不是公网部署方案。

新增入口：web_server.py、web/index.html、web/style.css、web/app.js、启动工作台.cmd。现有core.py与planner.py的业务算法未改。

## 本轮验证

使用本机Edge无头浏览器与Playwright验证；当前没有可调用的agent-browser工具，采用本地浏览器测试替代。修改前已留存workbench-before.png，修改后保留桌面、窄屏、结果和错误状态截图。

| 场景 | 实际结果 |
|---|---|
| 默认示例与计算 | HIGH先于LOW；B新增生产量分别80和200 |
| 修改任务数量 | 原结果立即失效，重算后更新数量 |
| 四张数据表 | 各表均可新增、删除，任务勾选随删除修正 |
| 小数数量、超安全整数、空任务、超额占用 | 阻断计算，显示问题；行字段错误可定位 |
| 大整数结果 | 18014398509481962准确显示，无浏览器舍入 |
| 采购余量示例 | 后期缺口由早期余量抵扣，后期采购量为0 |
| 日期风险 | 提前期导致过去日期时显示风险 |
| 计算中修改数据 | 丢弃过期响应，不混用不同输入版本 |
| 网络请求失败 | 显示失败，按钮可重试，恢复后计算成功 |
| 390px窄屏 | 页面整体不横向溢出，计算按钮可用，表格独立滚动 |
