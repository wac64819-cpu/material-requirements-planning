# 生产物料需求与采购计划系统 需求草案

版本：v0.1
日期：2026-09-24
项目：基于多层物料清单的生产需求计算与采购计划系统的设计与实现
文档性质：第一步的中文工作草案，供需求讨论、后续设计与验收使用；不是已完成的E1英文提交报告。
来源：本任务已读取的E1—E5及综合模板、已保存任务计划、用户选题与补充要求。
确认情况：用户已选择本题目，要求结构化方法，并明确库存分配“任务优先级优先”。其余规则为首版具体化建议，未冒充教师或小组已批准的规则。
小组人数：用户于2026-10-15确认2人。数量暂采用整数件；课程语言限制、截止及提交口径仍待核实。当前已采用Python过程式实现和本地Web工作台。

## 1 目标与用户

生产计划人员希望根据成品需求、产品组成和库存，得到自制件新增生产量、外购物料采购量及计划日期。
物料管理人员希望检查库存分配、缺口和采购凑整来源，不必手工逐层核算。
使用者应能够追溯“某项数量由哪些任务产生、抵扣了多少库存、为什么要买这么多”。

上述为业务使用场景，不要求首版实现多账号权限系统。
采用数据流分析、过程式函数分解与模块调用；本阶段不设计类继承体系。

## 2 首版范围

包含：单仓库，多生产任务，多层BOM，自制/外购物料，数据校验，按优先级共享库存，净需求计算，采购最小量与倍数，日历日提前期，交期风险，计划批次和来源明细，CSV导入导出。
不包含：真实采购下单/付款、财务核算、多个仓库、在途采购供给、生产损耗、安全库存、替代料、车间产能排程、供应商比价、工作日历。
没有纳入的因素不得暗中参与计算。计划只给建议，不代表供应商已交付或车间产能可行。库存快照基准日与计划基准日暂要求一致，避免把未来库存用于过去需求。
界面与编程语言后续确定；业务规则不依赖特定框架。

## 3 输入与输出

| 输入 | 最小业务字段 |
|---|---|
| 物料 | 唯一编号、名称、自制/外购类型、单位、提前期天数；外购物料另有最小采购量、采购倍数 |
| BOM关系 | 父项编号、子项编号、制造一件父项所需的子项数量 |
| 库存快照 | 物料编号、账面库存、已占用库存、快照基准日 |
| 生产任务 | 唯一编号、成品编号、需求数量、交货日期、优先级、是否本次参与计算 |
| 计划批次 | 计划基准日、选定任务、所用数据快照和规则版本 |

任务“需求数量”暂按成品交付需求解释，允许成品库存抵扣；输出另列“新增生产量”，避免把两者混为一谈。
若实际教学场景要求任务数量必须全部新生产，需要改动此规则及对应案例，不能只改页面文字。

输出包括：
1. 自制件计划：需求来源、毛需求、分配库存、净生产量、需要日期、计划开始日期。
2. 外购件计划：来源任务、净缺口、已利用计划余量、最小量/倍数调整、建议采购量、到货需求日期、建议下单日期。
3. 库存分配明细：任务、物料、分配前余额、占用量、分配后余额。
4. 风险与错误：阻断原因或交期风险、关联任务和材料、具体字段或记录位置。
5. 批次摘要与CSV：任务数、计划行数、采购项数、风险数及完整明细。不同物料单位不可简单相加成“总采购数量”。

## 4 业务规则

### BR01 数量和基础数据

首版暂按整数件数处理：任务需求和BOM用量为正整数；库存和提前期为非负整数。
优先级取1、2、3，1最高。最小采购量为非负整数，采购倍数为正整数，默认分别为0和1。
同一物料只使用一个固定单位，首版不进行单位换算。
编号去除首尾空白后唯一，区分大小写；日期必须是有效的YYYY-MM-DD日历日期。
小数数量暂不接受；此项仍待用户确认。禁止静默四舍五入。
账面库存不得小于已占用库存；未知物料不得当成零库存跳过；库存记录缺失作为阻断错误。

### BR02 BOM合法性

所有引用物料必须存在；同一父子关系不得重复；不得自引用或形成多节点循环。
外购件作为叶子，不允许挂下层BOM；参与计算的自制件需要有效BOM。
每次计算校验选定任务涉及的完整BOM及输入快照；发现阻断错误，整个批次不得产生标为有效的计划。
错误需定位到任务、物料或BOM关系。

### BR03 任务顺序【用户已确认优先级优先】

参与任务依次按优先级升序、交货日期升序、任务编号升序处理。
编号使用固定的序数比较，不依赖中文排序或系统区域设置。
高优先级任务即使交期晚，也先分配现有库存；同优先级才先处理较早交期。
修改文件行顺序不得改变结果。任务未选中时不占用本批次计算库存。
同一任务中，同一物料的需求按需要日期先后处理；同日同物料合并并保留各来源。

### BR04 库存快照和分配

初始可用库存 = 账面库存 - 已占用库存。
本次分配量 = min(当前计算余额, 当前需求量)。
净需求 = 当前需求量 - 本次分配量；分配后余额 = 分配前余额 - 本次分配量。
所有任务共享同一份批次内余额。余额不得为负，同一件库存不能重复分配。
计算和保存计划不改变实际库存，也不自动增加已占用库存。
首次及重复运行均从对应快照重新计算，不能把上次的临时余额作为新输入。

### BR05 多层需求与自制件

每项自制需求先抵扣可用库存，仅对净生产量展开下层BOM。
子项毛需求 = 父项净生产量 × BOM单件用量。
自制件按净需求精确生产，首版不设置自制件生产批量。
不同路径引用相同材料时按来源与日期汇总处理，不能因该物料之前被访问过而漏算，也不能重复展开已满足的数量。
自制件净需求为0时，不生成新增生产行，不产生其下层材料需求。
成品库存同样遵守上述规则；库存成品满足的部分不再消耗组件。

### BR06 外购缺口与采购批量

首先完成按任务优先级的现有库存分配，收集所有外购物料缺口。
采购阶段按“物料＋需要日期”汇总缺口；同一物料按需要日期从早到晚处理。
优先利用本批次此前已计划在该日期或之前到货的凑整余量，再计算当期剩余缺口q。
q=0时不生成采购行，即使最小采购量大于0。
q>0时：建议采购量 = ceil(max(q, 最小采购量) / 采购倍数) × 采购倍数。
本期采购量扣除q后的剩余量进入该物料的计划余量池，可满足后续日期缺口。
未来日期的采购余量不能满足更早的需求；计划余量不是实际库存，不得跨批次自动沿用。
同日缺口先合并再取整，不对每个任务分别凑整。
保存计划余量使用记录和最终剩余，避免报告只显示净缺口却遗漏实际建议采购量。

### BR07 日期倒推

时间粒度为日，使用日历日，不跳过周末或节假日。提前期可以为0。
根成品需要日期为任务交货日期。
自制件计划开始日期 = 该项需要日期 - 该项生产提前期。
它新生产所需的全部直接子项，需要日期为该自制件计划开始日期。
外购件建议下单日期 = 到货需求日期 - 该物料采购提前期。
同一物料不同需要日期保留不同日期段；子项提前期逐层累计，不能全部只从最终交货日期减一次。
提前期不随数量变化，不声称已经验证车间产能或供应商能力。

### BR08 交期风险

当任务交期或某个必须发生的生产/采购开始日期早于计划基准日时，标为风险，并保留原计算日期及提前天数。
日期等于基准日视为当日可开始；不自动把过去日期改成今天。
交期风险是可展示的计划结果；格式错误、BOM非法等属于阻断错误，两者分开。
存在交期风险时，可展示理论采购余量流向，但不能宣称整个计划按时可执行。

### BR09 批次、修改和导出

每个已保存批次记录任务、BOM、库存及参数快照与规则版本。
修改输入后重新计算形成新结果；历史批次保留原始结果。
同一快照和规则的数量、日期、分配顺序必须一致；批次ID和创建时间可以不同。
保存失败不得留下半份成功计划。CSV和界面中的同一项数量、日期、来源必须一致。
第一版不安排后台自动计算或真实库存扣账。

## 5 功能需求与验收条件

| 编号 | 用户需求 | 可验证的验收条件 |
|---|---|---|
| FR01 | 维护与导入基础数据 | 当用户提交物料、BOM、库存或任务时，系统应检查必填、编号、类型和取值；导入存在非法记录时应定位错误，不将该批导入标为全部成功 |
| FR02 | 选择任务并生成计算批次 | 当用户选择任务并计算时，系统应从固定快照开始，依BR03确定顺序；空任务集应提示“未选择任务” |
| FR03 | 检查BOM合法性 | 当选定任务涉及未知物料、非法用量或循环时，系统应阻断该次计划并给出相关记录 |
| FR04 | 计算多层需求 | 当自制件部分需求已由库存满足时，系统应只展开剩余生产数量，并保留父项和任务来源 |
| FR05 | 分配共享库存 | 当多个任务请求同一物料时，系统应按确认的优先级顺序共享余额，并确保每次分配后余额非负 |
| FR06 | 计算采购计划 | 当外购物料有缺口时，系统应按日期合并、利用此前计划余量，再应用最小量和倍数；零缺口不采购 |
| FR07 | 倒推日期和风险 | 当提前期造成建议开始日早于基准日时，系统应显示原日期和风险，而非静默改变计划 |
| FR08 | 查询、追溯与导出 | 当用户查看计划项时，系统应显示来源、抵扣、调整原因；导出应与所选批次一致 |

当前有八组主要功能；组员人数N未知，后续需确认功能数>N，并按课程要求继续分解，不得直接宣称人数要求已满足。

## 6 非功能需求草案

- NFR01 正确性：examples.md中的固定案例应与独立预期逐项一致；未实现前不标为软件测试通过。
- NFR02 可复现：在相同快照/规则下，仅改变输入行顺序不改变业务结果。
- NFR03 可追溯：每项净生产或采购数量能追溯到任务、BOM路径、库存分配及取整规则。
- NFR04 可用性：校验反馈应包含问题记录和原因；数量、日期、类型状态使用一致术语。
- NFR05 维护性：将校验、需求、库存、采购、日期、输出分成职责明确的过程式模块；接口在第二阶段设计。
- NFR06 性能验证范围：暂用200种物料、500条有效BOM边、100项任务且BOM深度不超过10的固定数据集开展性能测量。计算核心目标为本机10秒内完成。2026-10-12已在i7-14650HX上实测两组固定数据，核心5次采样最大值分别0.241秒、0.233秒；深度按BOM边数计。详见[性能验证](performance-v0.6.md)，不据此承诺任意同规模图形的最坏耗时。
- NFR07 数据完整性：计划失败不改变实际库存；保存操作成功或完整失败，不留下可被误认作完整结果的部分记录。

## 8 E1逻辑模型补充约定 2026-09-26

以下为本轮逻辑模型为可复现性补充的待评审约定，未冒充用户已确认：
- 同一任务、物料、日期合并后的来源分配按BOM路径固定序数，再按来源编号；只影响来源归属，不改变合并数量。
- 同一物料可用的计划余量先使用较早到货来源，同日再按来源桶编号；不允许未来余量反向抵扣。
- 单次基础数据导入采用全部校验通过才提交的建议策略；失败返回位置明确的错误。
