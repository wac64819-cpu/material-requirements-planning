# CSV导入导出 v0.5

日期：2026-10-12。保持过程式架构与简约界面，新增csv_io.py、导入校验接口、历史CSV下载接口和对应工作台入口。

## 操作流程

1. 展开“从CSV导入数据”，点击“下载四表示例模板”获取ZIP，解压后包含materials.csv、bom.csv、stocks.csv、tasks.csv。模板用的是本项目模拟数据，库存日期为2026-10-01，不代表当前日期。
2. 编辑所需CSV，在对应文件框选择一张或多张表。每个文件表示该表的完整替换内容，不是追加；未选中的表保持原样。若整套物料编号均已改变，建议四表一起导入。
3. 点击“校验所选文件”。系统校验所有文件及合并后数据，显示各表行数，出错时定位文件、行或关联记录，整个导入不应用。CSV行号指该记录结束时的实际文件行号，带换行的引号字段会占多行。
4. 校验通过后点击“应用并替换所选表”，候选数据进入编辑区。核对任务勾选、基准日，再点击“保存数据”。预览和应用都不会直接写数据库；保存沿用事务和版本冲突保护。
5. 生成计划或查看一份历史计划后，结果区选择需要的表并点击“下载CSV”。文件名包含完整批次编号。

校验期间修改数据或重新选文件会使旧预览失效。导入后的任务保留同编号的原勾选；新增任务不会自动勾选，已删除任务不再被选择。校验全部任务涉及的BOM和库存，而不是仅校验勾选任务。

## 文件与字段

采用UTF-8编码，可带BOM；逗号分隔，含逗号、双引号或换行的字段使用标准CSV引号规则。每个文件最多500KB、每表最多5000行，总提交仍受本地接口2MB限制。其他编码请另存为“CSV UTF-8”。不支持XLSX或分号分隔。

表头必须完整且无重复、未知列，列顺序可以调整：

| 表 | 表头 |
|---|---|
| 物料 | material_id,name,supply_type,unit,lead_time_days,min_purchase_qty,purchase_multiple |
| BOM | parent_id,child_id,qty_per |
| 库存 | material_id,on_hand,reserved,snapshot_date |
| 任务 | task_id,product_id,required_qty,due_date,priority |

物料类型为MAKE或BUY，优先级为1/2/3；编号和日期沿用现有规则。数量采用非负十进制整数，需求和用量必须大于零，不接受小数、科学计数法或超出页面安全整数范围的输入。最小采购量与采购倍数的空单元格分别按0、1处理；这两列仍需在表头中出现。日期使用YYYY-MM-DD，库存日期必须与界面基准日一致。

## 五类导出

| 类型 | 内容 |
|---|---|
| MAKE | 生产量、库存抵扣、需求与开始日期 |
| PURCHASE | 缺口、余量抵扣、采购数量、取整原因及缺口关联 |
| ALLOCATION | 每次库存分配前后余额、任务和需求编号 |
| TRACE | BOM路径、父需求、来源贡献量与该来源的库存抵扣/剩余 |
| RISK | 原始计算日期、早于基准日天数和风险来源 |

全部数据行带batch_id。采购量为0的余量抵扣记录保留，与页面一致；无风险时输出仅有表头的有效CSV。来源编号列表和路径在单元格中用JSON文字保存，可还原关联。

导出直接读取已保存的完整计划，不重新计算、不读取最新主数据；修改页面或保存新版本不会改变旧计划的导出。切换输入后旧结果的导出入口隐藏，可从历史重新查看并导出。

下载文件带UTF-8 BOM，正确引用逗号/引号/换行。可能被表格软件解释为公式的文本增加前置单引号，本程序再次导入时还原自身的保护前缀。大整数在CSV内完整保存，但表格软件自动将其识别为数字时可能丢精度，应以文本方式导入这些列。

## E5边界测试修正 2026-10-22

以上为v0.5阶段记录。E5外部黑盒测试发现：499999/500000字节的合法CSV若包含长字段，会触发csv解析器默认131072字符上限，错误返回CSV_SYNTAX。现已使用MAX_CSV_BYTES统一文件大小判断，并将字段解析上限提高到500000；文件UTF-8字节上限和5000条记录限制保持原值。BYTE0、BYTE1、BYTE2及原CSV回归38/38、浏览器CSV21/21通过。
