# 生产物料需求与采购计划系统 总体设计入口

版本：E2 v0.1，2026-09-26。
依据：requirements.md、examples.md、E1 v0.2及本轮重新读取的E2原文。
方法：结构化分析、过程式函数和普通数据记录，不采用类继承或对象交互建模。

## 六个子系统

| 子系统 | 责任 | 主入口 |
|---|---|---|
| S1 基础数据维护 | 解析导入、合并修改、校验、整批提交数据版本 | M10 maintain_sources |
| S2 快照与BOM校验 | 一致性读取、选择校验、无环检查、任务排序、冻结输入 | M20 prepare_context |
| S3 多层需求与共享库存 | 按任务优先级处理，先抵库存再展开净需求，保存来源 | M30 net_requirements |
| S4 采购与计划余量 | 按物料和日期汇总缺口，抵扣早期余量，按最小量和倍数取整 | M40 plan_purchases |
| S5 日期与交期风险 | 统一日历日运算、检查过去日期、整理完整计算结果 | M50 complete_plan |
| S6 历史、追溯与导出 | 整批保存、历史查询、来源追溯、按需CSV导出 | M60 publish_results |

M00负责选择操作并协调计算顺序：S2 → S3 → S4 → S5 → S6。基础数据维护走S1。
优先级分配现有库存与按日期计算采购在不同子系统完成，不得互相重排。

## 关键接口与状态责任

- S2返回PreparationResult：READY携带PreparedContext；INVALID携带无效计算结果，直接交给S6展示。
- S3独占本批次D3库存余额；叶子函数返回更新后的余额，由协调函数安装，不能修改真实库存。
- S4独占D4理论采购余量；禁止将其并入真实库存，禁止未来余量倒扣更早需求。
- M34和M44共用M52日期函数，避免采购和生产各自解释提前期。
- M14唯一提交基础数据修改，M62唯一提交完整计划；保存失败不得出现半份成功结果。
- 逻辑DFD携带的完整上下文由协调函数保留，叶子函数只接收和返回必要的数据片段。

## 本轮设计取舍

数据修改拟采用不可变版本，计划拟采用整份结果文档原子保存，优先保证历史可复现与实现清楚。这是设计建议，数据库产品与界面形式尚未确认；E2设计阶段没有创建数据库，后续计算原型进度见文末。
普通记录、列表、字典以及函数适配器即可表达这些接口，无需自定义类。

## 计算流程原型 v0.2（2026-09-26）

已串通 S2—S5 的内存计算路径：完整可达 BOM 校验、拓扑展开、优先级共享库存、按日期采购余量和风险。原型将部分 E2 叶子步骤合并在协调函数中，并不代表39个接口已逐一实现。

新计算流程114项检查、原有叶子38项检查均实际通过。三个可打开的结果示例位于 material-planning/results/demo-plans.html。详细映射与限制见 [英文阶段说明](implementation-v0.2.md)，参考项目见 [GitHub 查阅说明](github-references.md)。

S1数据维护、S6原子保存/历史/CSV、操作界面及规定规模性能测量仍待完成。演示JSON只保存计算证据，重跑可覆盖，不是已完成的历史批次功能；完整E3/E4/E5仍待补充。

## 本地操作界面 v0.3（2026-09-30）

按用户要求优先完成操作界面，再做保存功能。现在支持四类数据的页面内增删改、选择任务、计算、查看生产采购计划、库存与来源明细、错误定位和日期风险。采用白灰色与轻边框，蓝色强调主要操作。新增本机WSGI入口，不修改计算核心。

工作台浏览器验证30/30通过，已有计算验证114/114与38/38重新通过。详见 [工作台说明](workbench-v0.3.md)。S1目前仅实现临时编辑，不是基础数据版本提交；S6数据库、原子保存、历史、CSV及完整课程材料仍待完成。

## 保存与历史 v0.4（2026-09-30）

已用SQLite实现数据版本保存、并发版本检查、计划整批提交和历史快照查询；新增storage.py过程式适配器。物料/BOM/库存/任务以完整JSON版本文档保存，物理结构为三个表，原七张表设计保留为逻辑职责说明。

保存/API36项、保存与历史浏览器14项、原有界面回归30项检查通过。输入修改不会改变历史，保存失败整批回滚，测试数据库与正式数据库隔离。详见 [保存与历史说明](persistence-v0.4.md)。CSV、性能测量与完整E3—E5仍待完成。

## CSV接口 v0.5（2026-10-12）

已新增四表CSV导入预览及五类历史结果导出。导入先在副本上完成类型解析和整体校验，成功后由用户应用到编辑区，再通过已有保存流程提交；失败不更改原数据。导出直接读取不可变历史快照，所有结果行带批次标识。CSV解析与序列化为独立过程式函数，无新增业务类。

CSV检查38项、CSV浏览器21项通过，既有保存与界面回归36+14+30项通过。字段、替换语义、编码和测试边界见 [CSV说明](csv-v0.5.md)。核心业务流程已有导入—计算—保存—历史—导出路径，性能测量与完整E3—E5仍待补充。

## 规定规模验证 v0.6（2026-10-12）

新增两组200种物料、500条BOM边、100项任务的固定数据，覆盖共享库存与10条边的深层路径。没有变更原有算法或存储接口。核心各5次采样，最大0.241/0.233秒，低于10秒草案目标；另测完整WSGI计算保存与JSON输出、历史读取和浏览器真实操作。

47项核心/适配层检查及15项浏览器检查通过；数据、原始采样、环境、源码哈希和复现方法见[性能验证](performance-v0.6.md)。当前完整来源响应约9—10MB，大量表格仍一次显示，后续可通过分页及明细延迟加载改善浏览；密集深层交叉图不在本次两组拓扑范围内。完整E3—E5、人数与真实评审仍待完成。
